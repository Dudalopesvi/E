Do AutoVision para cá

mapa mental

Quase toda prova desse tipo é o mesmo problema com outro vocabulário. Descobrir qual peça do AutoVision corresponde a qual peça nova é metade do trabalho.

AutoVisionRede socialE-commerce
Vendedor (login)Usuário (funcionário ou cliente)Cliente (e/ou lojista)
AnúncioAtividade (corrida, caminhada, trilha)Produto
Interesse (contador)Curtida (toggle)Item no carrinho

Busca por modelo (ILIKE)Filtro por tipo de atividadeBusca de produtos

Diferença que muda tudo no e-commerce: dinheiro e estoque. Preço e total nunca podem vir do front-end, e o pedido precisa de transação. Isso não existia no AutoVision.

Banco de dados

~25 min

Tabelas da rede social (schema.sql)

São só estas quatro tabelas. O UNIQUE (usuario_id, atividade_id) em tb_curtida impede curtida duplicada direto no banco. Repare que nenhuma chave estrangeira tem ON DELETE CASCADE: isso afeta a exclusão (veja o backend).

-- schema.sql
CREATE TABLE tb_usuarios (
  id SERIAL PRIMARY KEY,
  nome VARCHAR(150) NOT NULL,
  email VARCHAR(150) NOT NULL UNIQUE,
  nome_usuario VARCHAR(150) NOT NULL,
  senha VARCHAR(100) NOT NULL,
  foto VARCHAR(255),
  tipo VARCHAR(20) NOT NULL CHECK (tipo IN ('funcionario', 'cliente')),
  createdat TIMESTAMP NOT NULL DEFAULT NOW(),
  updatedat TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE tb_atividade (
  id SERIAL PRIMARY KEY,
  tipo_atividade VARCHAR(20) NOT NULL CHECK (tipo_atividade IN ('corrida', 'caminhada', 'trilha')),
  distancia_percorrida INTEGER NOT NULL,   -- em metros
  duracao_atividade INTEGER NOT NULL,      -- em minutos
  quantidade_calorias INTEGER NOT NULL,
  createdat TIMESTAMP NOT NULL DEFAULT NOW(),
  updatedat TIMESTAMP NOT NULL DEFAULT NOW(),
  usuario_id INTEGER NOT NULL REFERENCES tb_usuarios(id)
);

CREATE TABLE tb_curtida (
  id SERIAL PRIMARY KEY,
  usuario_id INTEGER NOT NULL REFERENCES tb_usuarios(id),
  atividade_id INTEGER NOT NULL REFERENCES tb_atividade(id),
  createdat TIMESTAMP NOT NULL DEFAULT NOW(),
  UNIQUE (usuario_id, atividade_id)
);

CREATE TABLE tb_comentario (
  id SERIAL PRIMARY KEY,
  usuario_id INTEGER NOT NULL REFERENCES tb_usuarios(id),
  atividade_id INTEGER NOT NULL REFERENCES tb_atividade(id),
  texto VARCHAR(500) NOT NULL,
  createdat TIMESTAMP NOT NULL DEFAULT NOW()
);

Tabelas do e-commerce

Repare em preco_unitario em itens_pedido: é uma cópia do preço no momento da compra. Se o produto mudar de preço depois, o pedido antigo continua correto.

CREATE TABLE clientes (
  id SERIAL PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  senha VARCHAR(100) NOT NULL
);
CREATE TABLE produtos (
  id SERIAL PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  descricao TEXT,
  categoria VARCHAR(50),
  preco NUMERIC(10,2) NOT NULL CHECK (preco > 0),
  estoque INT NOT NULL DEFAULT 0 CHECK (estoque >= 0),
  imagem VARCHAR(255) NOT NULL
);
CREATE TABLE pedidos (
  id SERIAL PRIMARY KEY,
  cliente_id INT NOT NULL REFERENCES clientes(id),
  total NUMERIC(10,2) NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'pendente',
  criado_em TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE itens_pedido (
  id SERIAL PRIMARY KEY,
  pedido_id INT NOT NULL REFERENCES pedidos(id) ON DELETE CASCADE,
  produto_id INT NOT NULL REFERENCES produtos(id),
  quantidade INT NOT NULL CHECK (quantidade > 0),
  preco_unitario NUMERIC(10,2) NOT NULL
);

Backend — server.js

~45 min

Login e cadastro de usuário

O login devolve o usuário (sem a senha) e o front guarda em usuarioAtual. O erro 23505 do Postgres é violação de UNIQUE, aqui o e-mail repetido.

app.post('/api/login', async (req, res) => {
  const { email, senha } = req.body;
  const { rows } = await pool.query(
    'SELECT id, nome, nome_usuario, foto, tipo FROM tb_usuarios WHERE email=$1 AND senha=$2',
    [email, senha]);
  if (!rows[0]) return res.status(401).json({ erro: 'E-mail ou senha inválidos.' });
  res.json(rows[0]);
});

app.post('/api/usuarios', upload.single('foto'), async (req, res) => {
  const { nome, email, nome_usuario, senha, tipo } = req.body;
  if (!nome || !email || !nome_usuario || !senha)
    return res.status(400).json({ erro: 'Preencha todos os campos.' });
  if (!['funcionario', 'cliente'].includes(tipo))
    return res.status(400).json({ erro: 'Tipo inválido.' });
  const foto = req.file ? '/uploads/' + req.file.filename : null;
  try {
    await pool.query(
      'INSERT INTO tb_usuarios (nome, email, nome_usuario, senha, foto, tipo) VALUES ($1,$2,$3,$4,$5,$6)',
      [nome, email, nome_usuario, senha, foto, tipo]);
    res.status(201).json({ ok: true });
  } catch (e) {
    if (e.code === '23505') return res.status(409).json({ erro: 'E-mail já cadastrado.' });
    res.status(500).json({ erro: 'Erro ao cadastrar.' });
  }
});

Feed de atividades

Uma query traz a atividade, o autor, os contadores e se o usuário logado já curtiu. O ::int é necessário porque COUNT chega como string no pg.

app.get('/api/atividades', async (req, res) => {
  const uid = Number(req.query.usuario_id) || 0;
  const { rows } = await pool.query(`
    SELECT a.id, a.tipo_atividade, a.distancia_percorrida, a.duracao_atividade,
           a.quantidade_calorias, a.createdat, a.usuario_id,
           u.nome, u.nome_usuario, u.foto,
      (SELECT COUNT(*) FROM tb_curtida c WHERE c.atividade_id = a.id)::int AS curtidas,
      (SELECT COUNT(*) FROM tb_comentario m WHERE m.atividade_id = a.id)::int AS comentarios,
      EXISTS (SELECT 1 FROM tb_curtida c WHERE c.atividade_id = a.id AND c.usuario_id = $1) AS curti
    FROM tb_atividade a JOIN tb_usuarios u ON u.id = a.usuario_id
    ORDER BY a.createdat DESC`, [uid]);
  res.json(rows);
});

Registrar atividade (validação por campo)

app.post('/api/atividades', async (req, res) => {
  const { usuario_id, tipo_atividade, distancia_percorrida, duracao_atividade, quantidade_calorias } = req.body;
  const erros = {};
  if (!['corrida', 'caminhada', 'trilha'].includes(tipo_atividade))
    erros.tipo_atividade = 'Escolha corrida, caminhada ou trilha.';
  for (const [campo, v] of Object.entries({ distancia_percorrida, duracao_atividade, quantidade_calorias }))
    if (!Number.isInteger(Number(v)) || Number(v) <= 0)
      erros[campo] = 'Informe um número inteiro maior que zero.';
  if (Object.keys(erros).length) return res.status(400).json({ erros });

  await pool.query(
    `INSERT INTO tb_atividade (usuario_id, tipo_atividade, distancia_percorrida, duracao_atividade, quantidade_calorias)
     VALUES ($1,$2,$3,$4,$5)`,
    [usuario_id, tipo_atividade, distancia_percorrida, duracao_atividade, quantidade_calorias]);
  res.status(201).json({ ok: true });
});

Curtir (toggle) e comentar

app.post('/api/atividades/:id/curtir', async (req, res) => {
  const { usuario_id } = req.body, id = req.params.id;
  const del = await pool.query(
    'DELETE FROM tb_curtida WHERE atividade_id=$1 AND usuario_id=$2', [id, usuario_id]);
  if (del.rowCount === 0)
    await pool.query('INSERT INTO tb_curtida (atividade_id, usuario_id) VALUES ($1,$2)', [id, usuario_id]);
  const { rows } = await pool.query(
    'SELECT COUNT(*)::int AS total FROM tb_curtida WHERE atividade_id=$1', [id]);
  res.json({ curti: del.rowCount === 0, total: rows[0].total });
});

app.get('/api/atividades/:id/comentarios', async (req, res) => {
  const { rows } = await pool.query(
    `SELECT m.id, m.texto, m.createdat, u.nome_usuario
     FROM tb_comentario m JOIN tb_usuarios u ON u.id = m.usuario_id
     WHERE m.atividade_id=$1 ORDER BY m.createdat`, [req.params.id]);
  res.json(rows);
});

app.post('/api/atividades/:id/comentarios', async (req, res) => {
  const { usuario_id, texto } = req.body;
  if (!texto || !texto.trim()) return res.status(400).json({ erro: 'Comentário vazio.' });
  if (texto.length > 500) return res.status(400).json({ erro: 'Máximo de 500 caracteres.' });
  await pool.query(
    'INSERT INTO tb_comentario (atividade_id, usuario_id, texto) VALUES ($1,$2,$3)',
    [req.params.id, usuario_id, texto.trim()]);
  res.status(201).json({ ok: true });
});

Excluir atividade

Como o schema não tem ON DELETE CASCADE, apagar a atividade direto dá erro de chave estrangeira se houver curtida ou comentário. Apague os filhos primeiro, dentro de uma transação.

app.delete('/api/atividades/:id', async (req, res) => {
  const id = req.params.id, { usuario_id } = req.body;
  const dono = await pool.query('SELECT usuario_id FROM tb_atividade WHERE id=$1', [id]);
  if (!dono.rows[0]) return res.status(404).json({ erro: 'Atividade não encontrada.' });
  if (dono.rows[0].usuario_id !== Number(usuario_id))
    return res.status(403).json({ erro: 'Você só pode excluir suas atividades.' });

  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    await client.query('DELETE FROM tb_curtida WHERE atividade_id=$1', [id]);
    await client.query('DELETE FROM tb_comentario WHERE atividade_id=$1', [id]);
    await client.query('DELETE FROM tb_atividade WHERE id=$1', [id]);
    await client.query('COMMIT');
    res.json({ ok: true });
  } catch (e) {
    await client.query('ROLLBACK');
    res.status(500).json({ erro: 'Erro ao excluir.' });
  } finally { client.release(); }
});
Funcionário x cliente: o schema só diferencia pela coluna tipo. O que cada um pode fazer vem do enunciado; confira essa regra antes de decidir quem pode excluir ou ver o quê. Ao editar uma atividade ou usuário, lembre de gravar updatedat = NOW().

  const termo = '%' + (req.query.busca || '') + '%';

Finalizar pedido (transação)

O servidor busca o preço no banco, trava a linha do produto com FOR UPDATE, confere o estoque e só então grava. Se qualquer item falhar, o ROLLBACK desfaz tudo.

app.post('/api/pedidos', async (req, res) => {
  const { cliente_id, itens } = req.body; // itens: [{ produto_id, quantidade }]
  if (!Array.isArray(itens) || itens.length === 0)
    return res.status(400).json({ erro: 'Carrinho vazio.' });

  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    let total = 0; const linhas = [];
    for (const it of itens) {
      const { rows } = await client.query(
        'SELECT preco, estoque FROM produtos WHERE id=$1 FOR UPDATE', [it.produto_id]);
      if (!rows[0] || rows[0].estoque < it.quantidade) throw new Error('Estoque insuficiente.');
      total += Number(rows[0].preco) * it.quantidade;
      linhas.push({ ...it, preco: rows[0].preco });
      await client.query('UPDATE produtos SET estoque = estoque - $1 WHERE id=$2', [it.quantidade, it.produto_id]);
    }
    const ped = await client.query(
      'INSERT INTO pedidos (cliente_id, total) VALUES ($1,$2) RETURNING id', [cliente_id, total]);
    for (const l of linhas)
      await client.query(
        'INSERT INTO itens_pedido (pedido_id, produto_id, quantidade, preco_unitario) VALUES ($1,$2,$3,$4)',
        [ped.rows[0].id, l.produto_id, l.quantidade, l.preco]);
    await client.query('COMMIT');
    res.status(201).json({ pedido_id: ped.rows[0].id, total });
  } catch (e) {
    await client.query('ROLLBACK');
    res.status(400).json({ erro: e.message });
  } finally { client.release(); }
});

Front-end — app.js

~40 min

Renderizar atividade e curtir sem recarregar

A distância fica em metros no banco e é convertida só para exibir. Texto de usuário (nome, comentário) entra com textContent, nunca com innerHTML.

let usuarioAtual = null; // { id, nome, tipo } depois do login
const km = (m) => (m / 1000).toFixed(2).replace('.', ',') + ' km';

function criarAtividade(a) {
  const el = document.createElement('article');
  const titulo = document.createElement('strong');
  titulo.textContent = `${a.nome_usuario} · ${a.tipo_atividade}`;
  const dados = document.createElement('p');
  dados.textContent = `${km(a.distancia_percorrida)} em ${a.duracao_atividade} min · ${a.quantidade_calorias} kcal`;
  const btn = document.createElement('button');
  btn.textContent = (a.curti ? '♥ ' : '♡ ') + a.curtidas;
  btn.addEventListener('click', () => curtir(a.id, btn));
  el.append(titulo, dados, btn);
  return el;
}

async function curtir(id, btn) {
  if (!usuarioAtual) return alert('Faça login para curtir.');
  const r = await fetch(`/api/atividades/${id}/curtir`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ usuario_id: usuarioAtual.id })
  });
  const d = await r.json();
  btn.textContent = (d.curti ? '♥ ' : '♡ ') + d.total;
}

async function carregarFeed() {
  const uid = usuarioAtual ? usuarioAtual.id : 0;
  const lista = await (await fetch('/api/atividades?usuario_id=' + uid)).json();
  document.getElementById('feed').replaceChildren(...lista.map(criarAtividade));
}

Carrinho em memória e envio do pedido

O carrinho vive no front só para exibição. O que vai para o servidor são ids e quantidades; o total exibido aqui é informativo, quem manda é o servidor.

const brl = (v) => Number(v).toLocaleString('pt-BR', { style: 'currency', currency: 'BRL' });
let carrinho = []; // [{ produto_id, nome, preco, quantidade }]

function addAoCarrinho(p) {
  const item = carrinho.find((x) => x.produto_id === p.id);
  if (item) item.quantidade++;
  else carrinho.push({ produto_id: p.id, nome: p.nome, preco: p.preco, quantidade: 1 });
  renderCarrinho();
}

function renderCarrinho() {
  const total = carrinho.reduce((s, i) => s + Number(i.preco) * i.quantidade, 0);
  document.getElementById('totalCarrinho').textContent = brl(total);
  // ... montar a lista de itens com textContent ...
}

async function finalizarPedido() {
  if (carrinho.length === 0) return;
  const r = await fetch('/api/pedidos', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      cliente_id: usuarioAtual.id,
      itens: carrinho.map(({ produto_id, quantidade }) => ({ produto_id, quantidade }))
    })
  });
  const d = await r.json();
  if (!r.ok) return alert(d.erro);
  carrinho = []; renderCarrinho(); carregarVitrine();
}

Checklist e armadilhas

estratégia

Ordem sugerida em 3 horas

  • 0h00–0h20: banco, schema.sql, dados de teste, npm install, pasta public/uploads.
  • 0h20–1h10: rotas do server.js, testando cada uma no navegador ou no Postman antes de seguir.
  • 1h10–1h50: HTML e CSS essenciais: lista, formulários, modais.
  • 1h50–2h35: app.js: fetch, renderização, login, ação principal (curtir ou carrinho).
  • 2h35–3h00: validações por campo, teste de ponta a ponta, ajustes.

Erros comuns, nos dois temas

  • Pasta public/uploads inexistente: o Multer falha e a mensagem de erro não ajuda.
  • NUMERIC e COUNT chegam como string: use Number() ou ::int antes de somar ou comparar.
  • Query montada com concatenação: use sempre $1, $2. Concatenar abre SQL injection.
  • Validação só no front: repita no servidor. Quem corrige a prova pode chamar a API direto.
  • Erro genérico: mensagem específica por campo, não um alert único.

Específico da rede social

  • Exclusão sem CASCADE: apague tb_curtida e tb_comentario antes de tb_atividade, em transação.
  • Curtida duplicada: o UNIQUE protege no banco; não dependa só do botão.
  • Unidades: distância em metros, duração em minutos. Converta só na exibição.
  • Tipos fixos: valide tipo_atividade e tipo do usuário no servidor, igual ao CHECK.
  • Conteúdo do usuário: textContent em nome e comentário.

Específico do e-commerce

  • Total vindo do cliente: nunca confie. Recalcule no servidor com o preço do banco.
  • Estoque: confira dentro da transação, com FOR UPDATE, senão duas compras simultâneas vendem o último item duas vezes.
  • Preço histórico: grave preco_unitario no item do pedido.
  • Moeda: exiba com toLocaleString('pt-BR', { style: 'currency', currency: 'BRL' }).
Aviso honesto: este guia dá a estrutura, mas prova prática avalia se você consegue explicar e adaptar o que escreveu. Digite o código uma vez sem olhar, quebre de propósito, conserte. Quem só copia trava na primeira exigência que fuja do esqueleto.
