Guia da Prova — AutoVision

Passo a passo prático para construir o módulo de anúncios de veículos e registro de interesse exigido pelo enunciado, na ordem que gera mais pontos por minuto investido. O objetivo é sair do zero e chegar a uma aplicação funcional: banco → API → tela. Deixe estilo e detalhes visuais por último.

01

Setup do Projeto

~10 min

1. Extensões do VS Code para desenvolvimento offline

O autocomplete do Node.js (Express, pg, Multer) é nativo e funciona automaticamente offline assim que a pasta com a node_modules é aberta. Para agilizar a escrita de HTML, CSS e JavaScript sem internet, instale os arquivos .vsix das seguintes extensões:

• esbenp.prettier-vscode              // Formatação e identação automática de código

2. Arquitetura do Projeto

Para uma prova offline de 3 horas, essa é a estrutura mais simples possível que ainda atende 100% do enunciado. Não adicione TypeScript, build tools, frameworks de frontend (React/Vue) ou ORMs (Prisma/Sequelize) — cada camada extra é tempo que você não tem. pg puro com queries SQL diretas é mais rápido de escrever e de debugar sob pressão.

3. Comandos iniciais (rodar em ordem)

Executar no terminal, dentro da pasta do projeto. 

# inicializa o projeto
npm init -y

# dependências mínimas: servidor, banco, upload de imagem
npm install express pg multer

# pastas que o Express/multer vão precisar

Decisão que economiza tempo: não implemente login com sessão de servidor (express-session) nem hash de senha (bcrypt). Como o enunciado não exige recarregar a página, guarde o usuário logado em uma variável no app.js (memória do navegador) e envie o usuario_id junto de cada requisição que precisar dele (registrar interesse, cadastrar anúncio, ver perfil). Isso ainda atende 100% da especificação funcional e corta ~30 minutos de implementação.
02

Banco de Dados

~25 min

1. Estrutura das tabelas do banco de dados

O banco é composto por 4 tabelas: Usuários (somente vendedores fazem login e anunciam carros), Anúncios (criados pelo vendedor logado), Interesses (clientes não têm conta, então nome e contato vão direto no registro) e Mensagens (contato do cliente com o vendedor sobre um anúncio). 

-- schema.sql

-- 1. Usuários: somente vendedores fazem login e anunciam carros
CREATE TABLE usuarios (
  id SERIAL PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  usuario VARCHAR(50) UNIQUE NOT NULL,
  senha VARCHAR(100) NOT NULL,
  telefone VARCHAR(20),
  foto_perfil VARCHAR(255)
);

-- 2. Anúncios: criados pelo vendedor logado
CREATE TABLE anuncios (
  id SERIAL PRIMARY KEY,
  titulo VARCHAR(100) NOT NULL,
  local VARCHAR(100) NOT NULL,
  preco NUMERIC(10,2) NOT NULL,
  imagem VARCHAR(255) NOT NULL,
  vendedor_id INTEGER NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
  criado_em TIMESTAMPTZ DEFAULT NOW()
);

-- 3. Interesses: cliente não tem conta, então nome/contato vão direto no registro
CREATE TABLE interesses (
  id SERIAL PRIMARY KEY,
  anuncio_id INTEGER NOT NULL REFERENCES anuncios(id) ON DELETE CASCADE,
  cliente_nome VARCHAR(100) NOT NULL,
  cliente_contato VARCHAR(100) NOT NULL,
  criado_em TIMESTAMPTZ DEFAULT NOW()
);

-- 4. Mensagens: cliente entra em contato com o vendedor sobre um anúncio
CREATE TABLE mensagens (
  id SERIAL PRIMARY KEY,
  anuncio_id INTEGER NOT NULL REFERENCES anuncios(id) ON DELETE CASCADE,
  cliente_nome VARCHAR(100) NOT NULL,
  cliente_contato VARCHAR(100) NOT NULL,
  mensagem TEXT NOT NULL,
  criado_em TIMESTAMPTZ DEFAULT NOW()
);
Interesses e Mensagens sem conta: Como os clientes não precisam fazer login, seus dados de contato (cliente_nome e cliente_contato) são gravados diretamente nas tabelas interesses e mensagens referenciando o anúncio desejado (anuncio_id).

2. Rodando o schema no pgAdmin

Passo Ação
1 Abra o pgAdmin, crie um banco chamado autovision (clique direito em Databases → Create → Database).
2 Clique com o banco selecionado, abra a Query Tool.
3 Cole o conteúdo de schema.sql inteiro e execute (F5).
4 Confirme que as 4 tabelas aparecem em Schemas → public → Tables.

3. Importando o usuarios.csv do protótipo

O enunciado pede continuidade dos dados do protótipo. O jeito mais rápido offline é usar a ferramenta gráfica de importação do próprio pgAdmin — sem escrever código de import.

Passo Ação
1 Rode primeiro o CREATE TABLE usuarios do schema (a tabela precisa existir antes).
2 Clique direito na tabela usuarios → Import/Export Data...
3 Ative a chave "Import", selecione o arquivo usuarios.csv.
4 Na aba Options, marque Header se o CSV tiver cabeçalho, e confira o delimitador (geralmente , ou ;).
5 Na aba Columns, confirme se as colunas do CSV batem com as colunas da tabela; se os nomes forem diferentes, mapeie manualmente.
6 Clique em OK e depois confira com SELECT * FROM usuarios; na Query Tool.

1. Setup do Express + conexão com o banco

Importação das dependências essenciais (Express, PG, Multer, Path), configuração do middleware para servir arquivos estáticos na pasta public e criação do pool de conexões com o banco de dados PostgreSQL (autovision). 

const express = require('express');

const path = require('path');

const app = express();
app.use(express.json());

  database: 'autovision'

app.listen(3000, () =>
  console.log('Servidor rodando em http://localhost:3000')

2. Upload de imagem com multer

Configuração do armazenamento em disco (diskStorage) do Multer para salvar as imagens dos veículos na pasta public/uploads. Gera um nome único para cada arquivo combinando a data/hora em milissegundos com a extensão original do arquivo. 

const storage = multer.diskStorage({
  destination: 'public/uploads',
  filename: (req, file, cb) =>
    cb(null, Date.now() + path.extname(file.originalname))
});
const upload = multer({ storage });

3. Vitrine e busca por modelo

Rota de consulta (GET) que retorna os anúncios cadastrados. Executa um JOIN com a tabela de usuários para incluir os dados do vendedor e um LEFT JOIN agregando a quantidade total de demonstrações de interesse registradas. Permite filtrar dinamicamente por modelo através da query string ?modelo=. 

app.get('/api/anuncios', async (req, res) => {
  const { modelo } = req.query;
  const params = [];

  let query = `
    SELECT a.id, a.titulo, a.local, a.preco, a.imagem,
           u.nome AS vendedor, u.usuario AS vendedor_usuario, u.telefone AS vendedor_telefone,
           COUNT(i.id)::int AS interesses
    FROM anuncios a
    JOIN usuarios u ON u.id = a.vendedor_id
    LEFT JOIN interesses i ON i.anuncio_id = a.id
  `;

  if (modelo) {
    params.push(`%${modelo}%`);
    query += ` WHERE a.titulo ILIKE $${params.length}`;
  }

  query +=
    ' GROUP BY a.id, u.nome, u.usuario, u.telefone ORDER BY a.criado_em DESC';

  const { rows } = await pool.query(query, params);
  res.json(rows);
});
A rota busca os anúncios cadastrados realizando o JOIN com os dados do vendedor e contabilizando a quantidade total de interesses com COUNT(i.id). Permite filtrar os anúncios pelo título/modelo do veículo via parâmetro de query ?modelo=.

4. Rota de login

Endpoint de autenticação via POST. Valida as credenciais (usuário e senha) no banco de dados PostgreSQL. Se as credenciais forem válidas, retorna os dados cadastrais do vendedor; caso contrário, retorna HTTP Status 401 informando o erro. 

app.post('/api/login', async (req, res) => {
  const { usuario, senha } = req.body;
  const { rows } = await pool.query(
    'SELECT id, nome, usuario, telefone, foto_perfil FROM usuarios WHERE usuario = $1 AND senha = $2',
    [usuario, senha]
  );
  if (rows.length === 0) {
    return res
      .status(401)
      .json({ erro: 'Usuário não encontrado ou senha incorreta' });
  }
  res.json(rows[0]);
});

5. Registrar interesse no anúncio

Registra no banco a demonstração de interesse efetuada por qualquer visitante da plataforma. Insere o nome e contato fornecidos na tabela interesses e retorna o novo total de interações acumuladas naquele anúncio. 

app.post('/api/interesses/:anuncioId', async (req, res) => {
  const { anuncioId } = req.params;
  const { cliente_nome, cliente_contato } = req.body;

  if (!cliente_nome || !cliente_contato) {
    return res.status(400).json({ erro: 'Nome e contato são obrigatórios' });
  }

  await pool.query(
    'INSERT INTO interesses (anuncio_id, cliente_nome, cliente_contato) VALUES ($1, $2, $3)',
    [anuncioId, cliente_nome, cliente_contato]
  );

  const { rows } = await pool.query(
    'SELECT COUNT(*)::int AS total FROM interesses WHERE anuncio_id = $1',
    [anuncioId]
  );
  res.json({ interesses: rows[0].total });
});
Como os clientes não possuem conta cadastrada, o nome e contato fornecidos no formulário de interesse são gravados diretamente na tabela interesses associados ao ID do anúncio.

6. Perfil do vendedor (menu lateral)

Consulta consolidada que busca os veículos publicados por um determinado vendedor (vendedor_id), calculando tanto a contagem de anúncios quanto o somatório total de interesses recebidos em todas as suas publicações. 

app.get('/api/perfil/:id', async (req, res) => {
  const { id } = req.params;
  const anuncios = await pool.query(
    `
    SELECT a.id, a.titulo, a.local, a.preco, a.imagem, COUNT(i.id)::int AS interesses
    FROM anuncios a LEFT JOIN interesses i ON i.anuncio_id = a.id
    WHERE a.vendedor_id = $1 GROUP BY a.id ORDER BY a.criado_em DESC
  `,
    [id]
  );

  const totalInteresses = anuncios.rows.reduce(
    (acc, a) => acc + a.interesses,
    0
  );

  res.json({
    totalAnuncios: anuncios.rows.length,
    totalInteresses,
    anuncios: anuncios.rows
  });
});

7. Cadastrar e excluir anúncio

Endpoints para gerenciamento de anúncios. O método POST processa o formulário multipart enviando a imagem via Multer e salvando as informações no banco. O método DELETE remove permanentemente o anúncio informado pelo seu identificador (id). 

app.post('/api/anuncios', upload.single('imagem'), async (req, res) => {
  const { titulo, local, preco, vendedor_id } = req.body;
  if (!req.file) return res.status(400).json({ erro: 'Imagem obrigatória' });

  const { rows } = await pool.query(
    'INSERT INTO anuncios (titulo, local, preco, imagem, vendedor_id) VALUES ($1, $2, $3, $4, $5) RETURNING *',
    [titulo, local, preco, req.file.filename, vendedor_id]
  );
  res.json(rows[0]);
});

app.delete('/api/anuncios/:id', async (req, res) => {
  await pool.query('DELETE FROM anuncios WHERE id = $1', [req.params.id]);
  res.json({ ok: true });
});

8. Enviar mensagem ao vendedor

Recebe as mensagens diretas digitadas pelos potenciais compradores no modal, armazenando o nome, contato e o texto enviado na tabela mensagens. Por fim, inicia a execução do servidor Express escutando na porta local 3000. 

app.post('/api/mensagens/:anuncioId', async (req, res) => {
  const { anuncioId } = req.params;
  const { cliente_nome, cliente_contato, mensagem } = req.body;

  if (!cliente_nome || !cliente_contato || !mensagem) {
    return res
      .status(400)
      .json({ erro: 'Nome, contato e mensagem são obrigatórios' });
  }

  await pool.query(
    'INSERT INTO mensagens (anuncio_id, cliente_nome, cliente_contato, mensagem) VALUES ($1, $2, $3, $4)',
    [anuncioId, cliente_nome, cliente_contato, mensagem]
  );

  res.json({ ok: true });
});
Rota Método Usada por
/api/anuncios GET Vitrine inicial e busca por modelo do veículo (via ?modelo=)
/api/login POST Formulário de login de vendedores
/api/interesses/:anuncioId POST Modal de demonstração de interesse (nome e contato)
/api/perfil/:id GET Menu lateral "Ver Perfil" do vendedor
/api/anuncios POST Formulário de cadastro de veículo
/api/anuncios/:id DELETE Ícone de exclusão em "Seus anúncios"
/api/mensagens/:anuncioId POST Modal de envio de mensagem para o vendedor

// --- 1. VITRINE DE ANÚNCIOS ---
async function carregarVitrine(filtroModelo = '') {
  const params = new URLSearchParams();
  if (filtroModelo) params.append('modelo', filtroModelo);

  const url = `/api/anuncios${params.toString() ? '?' + params.toString() : ''}`;
  const resp = await fetch(url);
  const anuncios = await resp.json();

  if (filtroModelo && anuncios.length === 0) {
    document.getElementById('vitrine').innerHTML =
      '<p>Nenhum carro encontrado</p>';
    return;
  }
  renderizarVitrine(anuncios);
}

function formatarPreco(valor) {
  return Number(valor).toLocaleString('pt-BR', {
    style: 'currency',
    currency: 'BRL',
  });
}

// --- 6. CADASTRO DE NOVO ANÚNCIO (Com validações individuais) ---
document
  .getElementById('formCadastro')
  .addEventListener('submit', async (e) => {
    e.preventDefault();

    const campoTitulo = document.getElementById('campoTitulo');
    const campoLocal = document.getElementById('campoLocal');
    const campoPreco = document.getElementById('campoPreco');
    const campoImagem = document.getElementById('campoImagem');

    const erroTitulo = document.getElementById('erroTitulo');
    const erroLocal = document.getElementById('erroLocal');
    const erroPreco = document.getElementById('erroPreco');
    const erroImagem = document.getElementById('erroImagem');

    // Limpa erros anteriores
    erroTitulo.textContent = '';
    erroLocal.textContent = '';
    erroPreco.textContent = '';
    erroImagem.textContent = '';

    let temErro = false;

    // Validação do Título
    if (!campoTitulo.value.trim()) {
      erroTitulo.textContent = 'O título do anúncio é obrigatório.';
      temErro = true;
    }

    // Validação da Localização
    if (!campoLocal.value.trim()) {
      erroLocal.textContent = 'A localização é obrigatória.';
      temErro = true;
    }

    // Validação do Preço
    const precoNumero = parseFloat(campoPreco.value);
    if (!campoPreco.value || isNaN(precoNumero) || precoNumero <= 0) {
      erroPreco.textContent = 'Informe um preço válido maior que zero.';
      temErro = true;
    }

    // Validação da Imagem
    const arquivo = campoImagem.files[0];
    if (!arquivo) {
      erroImagem.textContent = 'Nenhum arquivo escolhido.';
      temErro = true;
    } else {
      const extensoesValidas = ['jpg', 'jpeg', 'png', 'gif', 'webp'];
      const extensao = arquivo.name.split('.').pop().toLowerCase();
      if (!extensoesValidas.includes(extensao)) {
        erroImagem.textContent =
          'Formato inválido (use JPG, JPEG, PNG, GIF ou WEBP).';
        temErro = true;
      }
    }

    if (temErro) return;

    // Envio para a API
    const formData = new FormData();
    formData.append('titulo', campoTitulo.value.trim());
    formData.append('local', campoLocal.value.trim());
    formData.append('preco', precoNumero);
    formData.append('vendedor_id', usuarioAtual.id);
    formData.append('imagem', arquivo);

    const resp = await fetch('/api/anuncios', {
      method: 'POST',
      body: formData,
    });

    if (resp.ok) {
      e.target.reset();
      carregarVitrine();
      document.getElementById('btnVerPerfil').click(); // Recarrega os dados do perfil
    }
  });

1. Ordem de execução recomendada nas 3 horas

Cronograma tático para gerenciar o tempo do exame, garantindo o funcionamento do fluxo principal (CRUD, Banco e Rotas) antes dos detalhes visuais e de validação.

  • 0h20 – 1h05 (45 min) | Backend e APIs (server.js): Implemente as rotas REST do Express: listagem e busca por modelo, login de vendedores, envio de mensagens, registro de interesses, perfil do vendedor, cadastro com upload de imagens via Multer e exclusão de anúncios. Teste as rotas rapidamente.
  • 1h05 – 1h45 (40 min) | Estrutura HTML e Estilização CSS: Monte a estrutura da vitrine, barra de busca, modais (Login, Interesse e Mensagem), painel de perfil do vendedor e formulário de cadastro. Aplique os estilos CSS essenciais para layout de cards, posicionamento de modais e responsividade básica.
  • 1h45 – 2h30 (45 min) | Integração Front-end JavaScript (app.js): Conecte a interface ao backend via fetch. Faça a carga dinâmica da vitrine, filtro por busca em tempo real/Enter, acionamento dos modais, fluxo de login/logout, botão de interesse com atualização do contador e envio de formulários sem recarregar a página.
  • 2h30 – 3h00 (30 min) | Validações, Testes de Ponta a Ponta e Ajustes: Aplique as mensagens de erro individuais campo a campo. Valide upload de imagens com extensões permitidas, formatação de preços em BRL, exclusão de anúncios no perfil e teste todos os fluxos como visitante e como vendedor logado.

2. Requisitos do enunciado fáceis de esquecer

Pontos críticos frequentemente avaliados em critérios de correção e pontuação que exigem atenção redobrada:

  • Pasta Físicas para Uploads: A pasta public/uploads deve existir fisicamente no diretório do projeto, e o middleware express.static('public') deve estar ativo. Caso contrário, o Multer falhará ao tentar salvar os arquivos enviados.
  • Validações Individuais por Campo: Exibir mensagens de erro específicas abaixo ou junto de cada campo inválido no formulário de cadastro (título vazio, preço zerado/negativo, extensão de arquivo incorreta como .pdf ou .exe), em vez de apenas um alerta genérico.
  • Comportamento Sem Reload (SPA): O envio de mensagens, registro de interesse, login e cadastro de anúncio devem atualizar a tela via manipulação de DOM/AJAX sem efetuar o recarregamento total da página (e.preventDefault() em formulários).
  • Diferenciação de Papéis (Visitante vs Vendedor): Visitantes não precisam de login para navegar na vitrine, filtrar por modelo, registrar interesse ou enviar mensagens. Apenas vendedores realizam login para publicar e excluir anúncios.
  • Contador de Interesses Dinâmico: Ao clicar no coração de interesse, a rota do backend deve retornar o total atualizado e o front-end deve atualizar a contagem visível do card e alterar a cor do ícone sem necessitar de busca completa na vitrine.
  • Busca Parcial e Case-Insensitive (ILIKE): A consulta SQL de busca por modelo deve usar o operador ILIKE com `%` em ambos os lados do termo pesquisado (ex: WHERE a.titulo ILIKE $1) para encontrar correspondências parciais independentemente de letras maiúsculas ou minúsculas.
  • Formatação de Moeda no Front-end: Garantir que os preços dos veículos vindos do banco (valores numéricos) sejam apresentados na vitrine no padrão brasileiro (R$ 0,00) utilizando Number(valor).toLocaleString('pt-BR', { style: 'currency', currency: 'BRL' }).
Dica de Ouro para o Exame: Comece garantindo que o banco de dados e as rotas do Node.js estejam funcionando. Uma API bem estruturada permite testar o front-end rapidamente e evita perder tempo corrigindo bugs de banco no final da prova.
